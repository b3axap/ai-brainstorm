## Architecture Decisions (unchanged)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Frontend | Vanilla JS | No build step, instant deploy on Replit |
| State | Global `state` object | Simple SPA, single source of truth |
| Real-time | Socket.IO | Bi-directional, room support built-in |
| Storage | In-memory | MVP speed; persistence is future work |
| AI | Anthropic streaming | Token-by-token UX for chat |
| Visualization | JSON → renderer functions | Decoupled agents from rendering |
| Chat rendering | marked.js (CDN) | Markdown in assistant messages |
| Export | html2canvas (lazy CDN) | PNG screenshots of artifact cards |

---

## Known Limitations (carried forward)

- No persistent storage (rooms lost on restart)
- No authentication (room code = access)
- File attachment (📎) is placeholder only
- Image agent is placeholder only
- No artifact versioning / undo
- No live cursors for multi-user canvas
- Kanban drag is visual-only (no server-side reorder)
- No artifact delete button

---

## Recommendations for v0.5.0

1. **Bump package.json** to v0.4.1 or v0.5.0
2. **Add missing Figma frames** — empty canvas state, @ mention dropdown, export buttons on artifact card
3. **Artifact delete** — add delete button to action bar, server-side removal + broadcast
4. **Kanban server-side reorder** — persist column changes via artifact-data-patch
5. **UI polish** — loading skeleton for artifacts during generation, better mobile UX
6. **Persistence** — consider SQLite or file-based storage for rooms/artifacts
